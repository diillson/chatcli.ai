Contributions are welcome, from a typo in these docs to a new provider or agent capability. ChatCLI is open source under the **Apache License 2.0**, and everyone taking part follows the [Code of Conduct](https://github.com/diillson/chatcli/blob/main/CODE_OF_CONDUCT.md).

The full guide lives in the repository: [CONTRIBUTING.md](https://github.com/diillson/chatcli/blob/main/CONTRIBUTING.md). This page summarizes it.

<Warning>
**Found a security problem?** Do not open an issue or a pull request. Report it privately as described in [SECURITY.md](https://github.com/diillson/chatcli/blob/main/SECURITY.md).
</Warning>

## Setup

You need Go at the version in `go.mod`, golangci-lint v2 and git.

```bash
git clone https://github.com/<you>/chatcli.git
cd chatcli
make build          # bin/chatcli, with version information
go test ./...       # the whole suite; it never touches your real ~/.chatcli
make lint           # golangci-lint run
```

To try your build against a model, log in from the prompt with `/auth login <provider>` or put an API key in a `.env` file (see [Installation](/start/installation)). The Kubernetes operator is a separate Go module: run its tests inside `operator/`.

## Making a change

1. Branch from `main` (`develop` is an automatically synced mirror).
2. Write the change and its tests. A bug fix comes with a test that fails without it.
3. Run `gofmt -w`, `make lint` and `go test ./...`.
4. Open a pull request against `main` with a [Conventional Commits](https://www.conventionalcommits.org/) title. Pull requests are squash-merged, and releases are cut by the maintainers with release-please.

Larger changes (a new provider, a builtin tool, a new surface, a change of defaults or security behavior) start with an issue to agree on the approach.

## Conventions

| Area | Rule |
|---|---|
| Go code | `gofmt`; `golangci-lint` with no issues and no `//nolint`; a license header on new files; no `TODO`, `FIXME`, `panic` or secrets in new production code; new functions up to cyclomatic complexity 30 |
| Public API | never remove or change an exported declaration: add a new one and keep the old one delegating |
| Dependencies | a new dependency needs maintainer approval |
| User-facing text | through `i18n.T`, in `en`, `en-US` and `pt-BR`, in a fragment file `i18n/locales/<tag>.<feature>.json` |
| Model-facing text | system prompts and tool descriptions stay in English |
| Providers | a capability is expected on every provider that can support it; a new provider is wired through every touch point of the [provider parity matrix](https://github.com/diillson/chatcli/blob/main/tools/qg/providerparity/providers.go) |
| Builtin tools | a semantic version in `Version()`, bumped whenever what the model sees changes (patch, minor, major); `TestBuiltinVersions` enforces it |
| Tests | hermetic: nothing writes to the real `~/.chatcli`; packages that touch the home store use `testenv.Main` |
| Commits | Conventional Commits with a single type; no `Co-Authored-By` trailers |
| Documentation | this site has every page in English and Portuguese: change both |

## What CI checks

Every pull request runs a quality gate with 15 floors:
- build and static analysis;
- coverage that may not drop, with 60% for new code;
- AI-generated-code smells;
- PR size;
- end-to-end tests;
- commit lint;
- complexity;
- secret scanning;
- i18n parity;
- CRD drift;
- license headers;
- API breaking changes;
- binary size;
- provider parity.

Security scans (`govulncheck`, `gosec`, CodeQL, Trivy and dependency review) run too. The [CONTRIBUTING.md](https://github.com/diillson/chatcli/blob/main/CONTRIBUTING.md#what-ci-checks) table gives each floor's threshold.

## Reporting bugs

Open an [issue on GitHub](https://github.com/diillson/chatcli/issues) with:

- the ChatCLI version (`chatcli --version`), your operating system, the provider and model;
- the steps to reproduce, the expected and the observed behavior;
- relevant logs (`LOG_LEVEL=debug`), with secrets removed.
