The **`@image`** tool generates **and edits** images through the **`llm/imagegen`** package. It is **multi-provider** and **local/keyless-first**.

- The AI can **list** the models every configured provider offers your account right now.
- It can **switch** backend or model when you ask ("use Gemini for images").
- It **edits** on the active backend, in that provider's own request format.

---

## Backend selection

`imagegen.NewFromEnv` picks the backend, and falls back to `null` when nothing is configured.

**`CHATCLI_IMAGE_PROVIDER` pins a backend.** Values: `sdwebui|url|openai|responses|google|xai|zai|minimax|bedrock`. In `auto` (or empty), the backend is chosen in this order:
1. **`CHATCLI_IMAGE_MODEL`:** the provider that serves the model. `gemini-nano-banana-2.1` routes to Google, `stability.*` to Bedrock, `grok-*` to xAI.
2. **`CHATCLI_IMAGE_URL`:** a self-hosted endpoint.
3. **The first provider with a credential:** OpenAI, Google, xAI, Z.AI, MiniMax.

| Backend | Credential | Default model |
|---|---|---|
| `openai` (Images API) | `OPENAI_API_KEY` | `gpt-image-2.5-flare` |
| `responses` (a chat model draws through the `image_generation` tool) | `OPENAI_API_KEY` | `gpt-5.6-sol` |
| `google` (Gemini / Nano Banana, `:generateContent`) | `GOOGLEAI_API_KEY` or `GEMINI_API_KEY` | `gemini-nano-banana-2.1` |
| `xai` (Grok Imagine) | `XAI_API_KEY` | `grok-imagine-image-2.0` |
| `bedrock` (Stability, `InvokeModel`) | the AWS chain of the Bedrock chat provider | `stability.stable-image-core-v1:1` |
| `zai` (GLM-Image) | `ZAI_API_KEY` | `glm-image` |
| `minimax` (Image-01) | `MINIMAX_API_KEY` | `image-01` |
| `sdwebui` (local Stable Diffusion WebUI) | `CHATCLI_IMAGE_URL` (keyless) | the server's checkpoint |
| `url` (OpenAI-compatible: LocalAI and similar) | `CHATCLI_IMAGE_URL` (+ `CHATCLI_IMAGE_KEY`) | the server's model |

<Info>
**One model serves both generation and editing.** `@image gen` and `@image edit` read the same `CHATCLI_IMAGE_PROVIDER` and `CHATCLI_IMAGE_MODEL`.
</Info>

## The @image tool

```text
<tool_call name="@image" args='{"cmd":"gen","args":{"prompt":"a watercolor fox","size":"1024x1024"}}' />
<tool_call name="@image" args='{"cmd":"edit","args":{"image":"/tmp/fox.png","prompt":"make it Pixar 3D, keep the composition"}}' />
<tool_call name="@image" args='{"cmd":"models"}' />
<tool_call name="@image" args='{"cmd":"use","args":{"model":"gemini-nano-banana-2.1"}}' />
<tool_call name="@image" args='{"cmd":"status"}' />
```

| Subcommand | Purpose |
|---|---|
| `gen {prompt, size?, n?, out?}` | Generate image(s) and save them. `out` is a file (1 image) or a directory (several). |
| `edit {prompt, image, images?, mask?, strength?, size?, n?, out?}` | Edit an existing image on the active backend (see the arguments below). |
| `models {provider?, live?}` | List each backend's models (see below). |
| `use {provider?, model?, for?}` | Switch the image backend and/or model for the session (see below). |
| `status` | Show the active backend, model and AWS region, whether it edits, the pinned edit backend and which backends are configured. |

**`edit` arguments**
- **`image`:** path to the input image.
- **`images`:** several input images, for models that take references.
- **`mask`:** PNG mask for inpainting. White marks the area to change. An unreadable mask fails the edit instead of repainting the whole image.
- **`strength`:** 0..1, how much to change the input.

**What `models` shows for each backend**
- Whether the backend is configured.
- The models it offers **your account now**. It uses the provider's own listing where one exists, and the catalog otherwise.
- For each model: gen/edit support, shutdown date and, on Bedrock, regions.
- `live:false` skips the network.

**How `use` switches**
- **Model only:** the provider that serves it is selected too.
- **Provider only:** that provider's default model is used.
- **`for:"edit"`:** pins the backend used for edits when the active one can't edit.
- **Refused switches:** a provider without its credential, and a model that has been shut down.

**In the coder, just ask:**
- "list the image models I have"
- "use Gemini for images"
- "switch to Stability SD3.5 on Bedrock"
- "remove the background of logo.png"

The AI calls `models`, then `use`, then `gen` or `edit`.

### Availability marks in `@image models`

```text
bedrock — configured
  ✓ stability.stable-image-core-v1:1               gen       (default)  [us-west-2]  Stable Image Core; fastest and cheapest.
  ✓ stability.sd3-5-large-v1:0                     gen+edit  [us-west-2]  SD3.5 Large; image-to-image with strength.
  ✓ stability.stable-image-inpaint-v1:0            edit      [us. profile: us-west-2,us-east-1]  Inpaint …
  ✓ stability.stable-outpaint-v1:0                 unsupported  …  Offered by Bedrock; @image has no request shape for it yet.
```

| Mark | Meaning |
|---|---|
| `✓` | The provider's listing offers it to your account now |
| `·` | From the catalog; the provider has no listing, or is not configured |
| `✗` | The listing ran and does not offer it to your account |

The listing has three more effects:
- **New ids show up:** a model the provider lists but the catalog doesn't know yet is shown and is usable.
- **Retired ids stay hidden:** an id the catalog knows is shut down stays out, even if the provider still lists it.
- **Shutdown dates are enforced:** a catalog model leaves the list on its shutdown day.

## Editing per provider

Every API edits in its own request shape. `@image edit` runs on the **active** backend, in that backend's contract. A backend that can't edit **fails before sending anything**. The edit never moves silently to another account.

| Backend | Generate | **Edit** | How |
|---|:---:|:---:|---|
| **OpenAI Images** (`gpt-image-2.5-*`, `gpt-image-2`) | ✅ | ✅ | `/images/edits` (multipart), mask supported |
| **OpenAI Responses** (`gpt-5.6-*`, `gpt-5.5`, `gpt-5.4-mini`) | ✅ | ✅ | same `/responses` call: `input_image` + `image_generation` with `action: "edit"` |
| **Google** (Gemini / Nano Banana) | ✅ | ✅ | `:generateContent` with inline image(s) |
| **xAI** (Grok Imagine) | ✅ | ✅ | `/images/edits` as JSON: input as data URI in `image.url` (`images[]` for several); no `size`; URL result downloaded |
| **Bedrock** | per model | per model | see the next section |
| **SD WebUI** | ✅ | ✅ | img2img, keyless and local |
| **Self-hosted** (`CHATCLI_IMAGE_URL`) | ✅ | ✅ / ❌ | multipart `/images/edits`; `CHATCLI_IMAGE_URL_EDITS=false` if the server only generates |
| Z.AI (GLM-Image / CogView) | ✅ | ❌ | the API only generates |
| MiniMax (Image-01) | ✅ | ❌ | the API only generates |

### Bedrock: regions, profiles and models

Bedrock image generation today means **Stability** models only. **Nova Canvas reached its end of life on 2026-09-30**, and Titan Image is gone. What changes per model is where it runs and whether it needs a profile.

**Generation and image-to-image: `stability.stable-image-core-v1:1`, `stability.stable-image-ultra-v1:1`, `stability.sd3-5-large-v1:0`.**
- They are offered **only in `us-west-2`**, In-Region.
- chatcli invokes them there even when `AWS_REGION` or `BEDROCK_REGION` points elsewhere.
- That mismatch is what used to fail with `The provided model identifier is invalid`.
- Core only generates. Ultra and SD3.5 Large also edit (`strength`).

**Image Services: inpaint, erase object, remove background, control sketch, control structure, style guide, and creative, conservative and fast upscale.**
- They take an input image (no text-to-image) and run **only through the US cross-region profile**.
- chatcli adds the `us.` prefix itself and invokes them from us-east-1, us-east-2 or us-west-2.
- **Inpaint** and **erase object** use the `mask`.
- **Remove background**, **erase object** and **fast upscale** ignore the prompt.
- `strength` maps to control strength (control models), fidelity (style guide) or creativity (creative upscale, at most 0.35).

| Bedrock model | Gen | Edit | Region / profile |
|---|:---:|:---:|---|
| `stability.stable-image-core-v1:1` (default) | ✅ | ❌ | us-west-2 |
| `stability.stable-image-ultra-v1:1` | ✅ | ✅ | us-west-2 |
| `stability.sd3-5-large-v1:0` | ✅ | ✅ | us-west-2 |
| `stability.stable-image-inpaint-v1:0` | ❌ | ✅ | `us.` profile |
| `stability.stable-image-erase-object-v1:0` | ❌ | ✅ | `us.` profile |
| `stability.stable-image-remove-background-v1:0` | ❌ | ✅ | `us.` profile |
| `stability.stable-image-control-sketch-v1:0` / `-control-structure-v1:0` | ❌ | ✅ | `us.` profile |
| `stability.stable-image-style-guide-v1:0` | ❌ | ✅ | `us.` profile |
| `stability.stable-creative-upscale-v1:0` / `-conservative-upscale-v1:0` / `-fast-upscale-v1:0` | ❌ | ✅ | `us.` profile |

`@image models` also lists the Bedrock models `@image` does not drive yet, marked `unsupported`: search-and-replace, search-and-recolor, outpaint and style transfer.

**Bedrock errors now say what to do:**
- Wrong region: the error names where the model exists.
- Missing profile: the error names the `us.` id to use.
- Missing model access: the error points to the Bedrock console.

## Editing on another backend: only when you pin it

When the active backend can't edit, `@image edit` sends no request. It returns a clear error naming the backend and model, for example Z.AI `glm-image` or Bedrock `stable-image-core`. Keys for other providers do **not** move the edit to them.

To edit on a different backend from the one that generates, pin it. The AI can do it with `@image use {"provider":"xai","for":"edit"}`, or you can set it yourself:

```bash
export CHATCLI_IMAGE_PROVIDER=zai            # generate with GLM-Image
export CHATCLI_IMAGE_EDIT_PROVIDER=sdwebui   # edit on local SD WebUI (keyless)
export CHATCLI_IMAGE_EDIT_MODEL=             # optional model for the edit backend
```

The reply then says so:

> ℹ️ Image backend `"zai"` does not edit images; this edit ran on `"sdwebui"`, as CHATCLI_IMAGE_EDIT_PROVIDER pins.

- `CHATCLI_IMAGE_EDIT_PROVIDER` accepts `sdwebui`, `url`, `openai`, `responses`, `google`, `xai`, `zai`, `minimax`, `bedrock`.
- It is only used when the active backend can't edit.
- If the pinned backend can't edit either (missing key or a generate-only model), the error says that too.

## Commands

```text
@image models                                  # per backend, live where the provider lists models
/model-image gemini-nano-banana-2.1            # model + the provider that serves it (gen and edit)
/config image                                  # overview (backend, api, model, url, edit backend)
/config image models                           # same listing as @image models
/config image model stability.sd3-5-large-v1:0 # same as /model-image
/config image edit xai                         # backend used for edits when the active one can't edit
/config image provider responses               # pin a backend
/config image api responses                    # OpenAI: Images vs Responses
/config image reset                            # clear every override above
```

- `/model-image`, `/config image model` and `@image use` select the **backend that serves the model**. Picking a Gemini model while the provider is pinned to xAI therefore switches to Google instead of sending a Gemini id to xAI.
- These switches last for the session. To keep one, set `CHATCLI_IMAGE_PROVIDER`/`CHATCLI_IMAGE_MODEL` (or `CHATCLI_IMAGE_EDIT_PROVIDER`/`CHATCLI_IMAGE_EDIT_MODEL`) in `.env`.

## Formats & details

- **OpenAI edits** accept `image/jpeg`, `image/png` and `image/webp` (not `gif`). The multipart part's `Content-Type` comes from the image bytes.
- **SD WebUI img2img** maps `strength` to `denoising_strength`. The default is `0.6`: a visible change that preserves the structure.
- **Bedrock Stability:**
  - text-to-image sends an `aspect_ratio`;
  - SD3.5 Large edits with `mode: image-to-image` + `strength`;
  - Ultra edits with `image` + `strength`;
  - the Image Services send the fields each one takes.

## Privacy & cost

- **Local Stable Diffusion WebUI** is keyless and generates **and** edits on your machine. It is the private, zero-cost option.
- Cloud backends use **your own** keys.
- Confirm before generating or editing large batches, and mention the cost when it matters.
