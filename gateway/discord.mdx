The Discord adapter connects out to the **Discord Gateway** over a WebSocket, so like Telegram it needs no public URL and opens no port. The bot reads every message in the channels and DMs it can see, so a required sender allow-list — on top of Discord's own channel permissions — decides who it answers.

| | Discord |
| --- | --- |
| Transport | Discord Gateway WebSocket v10; no port is opened |
| Who can talk to the bot | Senders in `CHATCLI_DISCORD_ALLOWED_USERS` (required); `*` opens it to everyone |
| Voice notes in | Yes, an audio attachment |
| Voice replies | No (text only) |
| Images in | Yes |
| Images out | Yes |
| "Working on it" signal | One short text notice if the reply takes more than about 2 seconds |

## Set it up

<Steps>
  <Step title="Create the application and bot">
    In the Discord Developer Portal, create an application, add a **Bot** and copy its token.
  </Step>
  <Step title="Turn on the Message Content intent">
    Under **Bot → Privileged Gateway Intents**, enable **Message Content Intent**. The gateway requests it to read what people write; without it Discord refuses the connection.
  </Step>
  <Step title="Invite the bot">
    Use the OAuth2 URL generator with the `bot` scope and the permissions to read messages, send messages and attach files, then open the URL and add the bot to your server. Direct messages to the bot work as well.
  </Step>
  <Step title="Configure ChatCLI and start">
    ```bash
    export CHATCLI_DISCORD_BOT_TOKEN="..."
    export CHATCLI_DISCORD_ALLOWED_USERS="123456789012345678"  # author snowflakes; required to start
    ```

    ```text
    /gateway start
    /gateway status     # discord should be listed
    ```
  </Step>
</Steps>

## Environment variables

| Variable | Required | Default | What it does |
| --- | --- | --- | --- |
| `CHATCLI_DISCORD_BOT_TOKEN` | yes | — | The bot token. The adapter starts only when it is set. |
| `CHATCLI_DISCORD_ALLOWED_USERS` | yes | — | Author snowflake IDs allowed to talk to the bot, separated by commas, spaces or semicolons. **The adapter refuses to start without it.** Set it to `*` to open the bot to everyone, which logs a warning at every start. |
| `CHATCLI_DISCORD_HOME_CHANNEL` | no | — | Default channel ID for [proactive messages](/gateway/proactive-messaging) sent with `@send discord`. |

## Who can reach the bot

<Warning>
The bot answers messages from senders in `CHATCLI_DISCORD_ALLOWED_USERS`, in every server channel and DM it can read; it does not wait for a mention, and the adapter **refuses to start without the list**. Each message runs the agent with its tools and shell, so list only the people who should use it; set it to `*` only when the bot is meant to be public.
</Warning>

<Note>
**New in the security release:** Discord now needs a sender allow-list like every other channel. IDs are the author's snowflake. A sender who is not on the list gets **no reply, and their voice notes and images are not downloaded**. The public `*` value is an explicit opt-in that logs a warning at every start. See the [security hardening upgrade](/security/hardening-upgrade).
</Note>

Messages written by bots, including this one, are ignored.

## Messages

- **Text**: the message content. A server channel is one conversation shared by everyone in it; a DM is its own.
- **Voice**: the first audio attachment is downloaded and transcribed before the agent runs.
- **Images**: the first image attachment reaches the model.
- **Image replies** are uploaded as a file on the reply; on failure the text is sent alone.
- **Long replies** go out as several messages in order, split at line breaks or spaces, because Discord accepts at most 2000 characters per message.
- Replies are posted in the channel, not as a reply to the original message.

## Limits

- A reply is cut at **3500 characters** before it is split, so it arrives as at most two messages.
- After a disconnect the bot reconnects with a new session; messages sent during the gap are not delivered to it.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The bot is online but never answers">
    Enable the **Message Content Intent** in the Developer Portal. Without it the gateway cannot read message text and the connection is refused; `~/.chatcli/gateway.log` shows the error.
  </Accordion>
  <Accordion title="The bot answers in channels it should not">
    Remove its permission to read those channels in the server settings, or narrow `CHATCLI_DISCORD_ALLOWED_USERS` to the senders who should reach it.
  </Accordion>
</AccordionGroup>
