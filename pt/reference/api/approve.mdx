---
title: "Aprovar Solicitação"
openapi: "POST /approvals/{name}/approve"
description: "Aprova uma solicitação de aprovação, permitindo que a remediação seja executada"
icon: "circle-check"
---

<ParamField path="name" type="string" required>
  Nome da solicitação de aprovação (ex.: `approval-payment-service-oom-kill-1773933600-plan-1`)
</ParamField>

<ParamField query="namespace" type="string">
  Namespace do Kubernetes. Se omitido, todos os namespaces são pesquisados (primeira ocorrência).
</ParamField>

<ParamField body="approver" type="string" required>
  Quem está aprovando a solicitação. Valor vazio retorna `400`.
</ParamField>

<ParamField body="reason" type="string">
  Justificativa opcional
</ParamField>

A chamada define `status.state` da solicitação como `Approved`; o operator então reage ao novo estado: o RemediationPlan que aguardava a aprovação passa para `Executing`. A resposta traz o item atualizado em `spec` e `resourceMeta` (sem `status`).

<Warning>
**Limitações da decisão via REST (versão atual):**

- **O aprovador e o motivo não são gravados.** O handler também escreve `status.approvedBy`, `status.decisionReason` e `status.decidedAt`, mas o CRD ApprovalRequest não define esses campos, então o API server do Kubernetes os descarta. Só a mudança de estado persiste; a resposta e os GETs seguintes os mostram vazios, e nenhuma entrada é adicionada a `status.decisions`.
- **Sem checagem de estado ou expiração.** A solicitação não precisa estar `Pending`: uma já decidida ou `Expired` é sobrescrita, e não há `409`/`410`.
- **O quórum é ignorado.** Uma única chamada decide a solicitação mesmo quando a regra exige vários aprovadores.

Para registrar quem decidiu e por quê (e passar pelo caminho de decisão do próprio controller, incluindo quórum), anote o ApprovalRequest:

```bash
kubectl -n production annotate approvalrequest approval-payment-service-oom-kill-1773933600-plan-1 \
  platform.chatcli.io/approve="oncall-sre:aumento de memória confirmado"
```

O valor é `<aprovador>:<motivo>`; o controller o adiciona a `status.decisions` e remove a annotation.
</Warning>
