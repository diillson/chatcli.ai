---
title: "Adiar Incidente"
openapi: "POST /incidents/{name}/snooze"
description: "Segura as notificações e o escalonamento de um incidente por um período"
icon: "clock"
---

<ParamField path="name" type="string" required>
  Nome do recurso Issue (ex.: `payment-service-oom-kill-1773933600`)
</ParamField>

<ParamField query="namespace" type="string">
  Namespace do incidente. Se omitido, todos os namespaces são pesquisados (primeira ocorrência).
</ParamField>

<ParamField body="duration" type="string" required>
  Duração do snooze no formato de duração do Go (ex.: `30m`, `1h`, `2h30m`). Precisa ser positiva; não há máximo.
</ParamField>

A chamada adiciona `aiops.chatcli.io/snoozed-until` (agora + `duration`, RFC 3339) e `aiops.chatcli.io/snoozed-by` (a **role** da API key que chamou) ao Issue e retorna o incidente atualizado. Outros campos do corpo são ignorados.

<Note>
O controller de notificação respeita o snooze até `snoozed-until`:

- Nenhuma notificação de mudança de estado é enviada, exceto `Resolved` (o PagerDuty e o OpsGenie precisam dela para fechar o page).
- O escalonamento segura o nível atual. Uma notificação de nível que cai dentro do snooze fica retida (annotation `platform.chatcli.io/escalation-pending-notify`) e sai quando o snooze termina, e o timeout do nível recomeça a partir desse momento.

A remediação não é afetada. A `duration` precisa ser positiva: zero ou um valor negativo retorna `400`.
</Note>

<RequestExample>
```bash curl
curl -X POST -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"duration": "30m"}' \
  http://localhost:8090/api/v1/incidents/payment-service-oom-kill-1773933600/snooze
```
</RequestExample>
