---
title: "Obter Error Budget do SLO"
openapi: "GET /slos/{name}/budget"
description: "Retorna os números de error budget de um SLO"
icon: "coins"
---

<ParamField path="name" type="string" required>
  Nome do SLO (ex.: `payment-availability`)
</ParamField>

<ParamField query="namespace" type="string">
  Namespace do SLO. Se omitido, todos os namespaces são pesquisados.
</ParamField>

Role mínima: `viewer`. A resposta tem apenas `spec` (sem `status` nem `resourceMeta`) e todos os campos sempre aparecem. Não há histórico, previsão nem opção de granularidade.

- `currentValue` e `errorBudgetRemaining` são percentuais; `errorBudgetTotal` é uma fração (`1 - target/100`) e `errorBudgetUsed` é a parte usada, na mesma unidade.
- `burnRate` é a taxa de consumo de 1 hora do controller (`status.burnRate1h`; `1.0` = consumindo o budget exatamente no ritmo previsto). As taxas de 6h, 24h e 72h estão em [Obter SLO](/pt/reference/api/get-slo).
- `state` é `Healthy`, `AtRisk` ou `Breached` (veja [Listar SLOs](/pt/reference/api/list-slos)) e vem vazio antes do primeiro cálculo do controller.

<ResponseExample>
```json Response 200
{
  "apiVersion": "v1",
  "kind": "SLOBudget",
  "spec": {
    "name": "payment-availability",
    "target": 99.9,
    "currentValue": 99.95,
    "errorBudgetTotal": 0.001,
    "errorBudgetUsed": 0.0005,
    "errorBudgetRemaining": 50,
    "burnRate": 0.8,
    "window": "30d",
    "state": "Healthy"
  }
}
```
</ResponseExample>
