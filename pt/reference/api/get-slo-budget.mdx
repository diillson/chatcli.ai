---
title: "Obter Error Budget do SLO"
openapi: "GET /slos/{name}/budget"
description: "Retorna os números de error budget de um SLO"
icon: "coins"
---

<ParamField path="name" type="string" required>
  Nome do SLO (ex.: `payment-availability`)
</ParamField>

<ParamField query="namespace" type="string">
  Namespace do SLO. Se omitido, todos os namespaces são pesquisados.
</ParamField>

Role mínima: `viewer`. A resposta tem apenas `spec` (sem `status` nem `resourceMeta`) e todos os campos sempre aparecem. Não há histórico, previsão nem opção de granularidade.

- `currentValue` e `errorBudgetRemaining` são percentuais; `errorBudgetTotal` é uma fração (`1 - target/100`).
- `burnRate` é calculado aqui como `errorBudgetUsed / errorBudgetTotal`, uma razão, e não uma taxa de consumo por janela de tempo. Como o controller de SLO não grava `status.errorBudgetUsed` na versão atual, `errorBudgetUsed` e `burnRate` vêm `0` e `state` vem vazio. As taxas de consumo multi-janela do controller ficam no próprio recurso: `kubectl get slo <nome> -o jsonpath='{.status.burnRate1h}'` (também `burnRate6h`, `burnRate24h`, `burnRate72h`).

<ResponseExample>
```json Response 200
{
  "apiVersion": "v1",
  "kind": "SLOBudget",
  "spec": {
    "name": "payment-availability",
    "target": 99.9,
    "currentValue": 99.95,
    "errorBudgetTotal": 0.001,
    "errorBudgetUsed": 0,
    "errorBudgetRemaining": 50,
    "burnRate": 0,
    "window": "30d",
    "state": ""
  }
}
```
</ResponseExample>
