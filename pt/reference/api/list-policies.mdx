---
title: "Listar Políticas"
openapi: "GET /policies/{kind}"
description: "Lista objetos ApprovalPolicy, NotificationPolicy, EscalationPolicy ou IncidentSLA com spec e status brutos — somente leitura"
icon: "list-check"
---

<ParamField path="kind" type="string" required>
  `approval`, `notification`, `escalation` ou `sla`
</ParamField>

<ParamField query="namespace" type="string">
  Filtrar por namespace. Vazio lista todos os namespaces.
</ParamField>

<ParamField query="page" type="integer" default="1">
  Número da página
</ParamField>

<ParamField query="pageSize" type="integer" default="20">
  Itens por página (máximo 100)
</ParamField>

As políticas são escritas via `kubectl` ou GitOps, onde são revisadas; a API e a aba Políticas do dashboard só as leem. Cada item carrega o `spec` e o `status` do CRD sem alteração, então os campos seguem as definições de [ApprovalPolicy](/pt/kubernetes/aiops/approval-workflow), [NotificationPolicy e EscalationPolicy](/pt/kubernetes/aiops/notifications) e [IncidentSLA](/pt/kubernetes/aiops/slo-sla).

Role mínima: `viewer`. Qualquer método diferente de `GET` retorna `405`; um `kind` desconhecido retorna `404`. Os itens não são filtrados por status nem ordenados.

<ResponseExample>
```json Response 200
{
  "apiVersion": "v1",
  "kind": "ApprovalPolicyList",
  "metadata": { "totalCount": 1, "page": 1, "pageSize": 20 },
  "items": [
    {
      "name": "prod-rollbacks",
      "namespace": "production",
      "kind": "ApprovalPolicy",
      "creationTimestamp": "2026-09-01T12:00:00Z",
      "spec": {
        "enabled": true,
        "rules": [
          { "name": "rollback-requires-human", "match": { "actionTypes": ["RollbackDeployment"] }, "mode": "manual", "timeoutMinutes": 30, "requiredApprovers": 1 }
        ]
      },
      "status": { "totalApproved": 7, "totalRejected": 1 }
    }
  ]
}
```

```json Response 404
{
  "apiVersion": "v1",
  "kind": "Error",
  "error": "Not Found",
  "code": 404,
  "message": "unknown policy kind: approvals"
}
```
</ResponseExample>
