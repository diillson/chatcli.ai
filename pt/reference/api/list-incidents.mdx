---
title: "Listar Incidentes"
openapi: "GET /incidents"
description: "Retorna a lista de incidentes (recursos Issue) com filtros opcionais e paginação"
icon: "list"
---

Cada item é um custom resource `Issue` projetado no formato de incidente abaixo. Os filtros são de igualdade exata e combinados com AND.

<ParamField query="namespace" type="string">
  Só incidentes deste namespace do Kubernetes. Omita para listar todos os namespaces.
</ParamField>

<ParamField query="severity" type="string">
  Filtrar por severidade: `critical`, `high`, `medium`, `low`
</ParamField>

<ParamField query="state" type="string">
  Filtrar por estado: `Detected`, `Analyzing`, `Remediating`, `Contained`, `Resolved`, `Escalated`, `Failed`
</ParamField>

<ParamField query="from" type="string">
  Só incidentes criados a partir deste horário RFC 3339 (ex.: `2026-03-19T00:00:00Z`)
</ParamField>

<ParamField query="to" type="string">
  Só incidentes criados até este horário RFC 3339
</ParamField>

<ParamField query="page" type="integer" default="1">
  Número da página
</ParamField>

<ParamField query="pageSize" type="integer" default="20">
  Itens por página (máximo 100)
</ParamField>

<Note>
`requiresHumanAction` é `true` quando o incidente está `Contained` (o operator silenciou o workload e uma pessoa precisa restaurá-lo), e `requiredAction` diz o que fazer. `chaosInduced` / `chaosExperiment` aparecem quando o incidente foi correlacionado a um ChaosExperiment ativo. Campos opcionais vazios são omitidos.
</Note>
