O tool **`@image`** gera **e edita** imagens via o pacote **`llm/imagegen`**. É **multi-provedor** e **local/keyless-first**.

- A IA pode **listar** os modelos que cada provedor configurado oferece à sua conta neste momento.
- Ela pode **trocar** de backend ou de modelo quando você pede ("use o Gemini para imagens").
- Ela **edita** no backend ativo, no formato de requisição do próprio provedor.

---

## Seleção de backend

`imagegen.NewFromEnv` escolhe o backend e cai para `null` quando nada está configurado.

**`CHATCLI_IMAGE_PROVIDER` fixa um backend.** Valores: `sdwebui|url|openai|responses|google|xai|zai|minimax|bedrock`. Em `auto` (ou vazio), o backend é escolhido nesta ordem:
1. **`CHATCLI_IMAGE_MODEL`:** o provedor que serve o modelo. `gemini-nano-banana-2.1` vai para o Google, `stability.*` para o Bedrock, `grok-*` para a xAI.
2. **`CHATCLI_IMAGE_URL`:** um endpoint self-hosted.
3. **O primeiro provedor com credencial:** OpenAI, Google, xAI, Z.AI, MiniMax.

| Backend | Credencial | Modelo padrão |
|---|---|---|
| `openai` (Images API) | `OPENAI_API_KEY` | `gpt-image-2.5-flare` |
| `responses` (um modelo de chat desenha via a tool `image_generation`) | `OPENAI_API_KEY` | `gpt-5.6-sol` |
| `google` (Gemini / Nano Banana, `:generateContent`) | `GOOGLEAI_API_KEY` ou `GEMINI_API_KEY` | `gemini-nano-banana-2.1` |
| `xai` (Grok Imagine) | `XAI_API_KEY` | `grok-imagine-image-2.0` |
| `bedrock` (Stability, `InvokeModel`) | a cadeia AWS do provider de chat Bedrock | `stability.stable-image-core-v1:1` |
| `zai` (GLM-Image) | `ZAI_API_KEY` | `glm-image` |
| `minimax` (Image-01) | `MINIMAX_API_KEY` | `image-01` |
| `sdwebui` (Stable Diffusion WebUI local) | `CHATCLI_IMAGE_URL` (keyless) | o checkpoint do servidor |
| `url` (OpenAI-compatível: LocalAI e similares) | `CHATCLI_IMAGE_URL` (+ `CHATCLI_IMAGE_KEY`) | o modelo do servidor |

<Info>
**Um único modelo serve para gerar e editar.** `@image gen` e `@image edit` leem o mesmo `CHATCLI_IMAGE_PROVIDER` e `CHATCLI_IMAGE_MODEL`.
</Info>

## Tool @image

```text
<tool_call name="@image" args='{"cmd":"gen","args":{"prompt":"a watercolor fox","size":"1024x1024"}}' />
<tool_call name="@image" args='{"cmd":"edit","args":{"image":"/tmp/fox.png","prompt":"make it Pixar 3D, keep the composition"}}' />
<tool_call name="@image" args='{"cmd":"models"}' />
<tool_call name="@image" args='{"cmd":"use","args":{"model":"gemini-nano-banana-2.1"}}' />
<tool_call name="@image" args='{"cmd":"status"}' />
```

| Subcomando | Função |
|---|---|
| `gen {prompt, size?, n?, out?}` | Gera imagem(ns) e salva. `out` é um arquivo (1 imagem) ou um diretório (várias). |
| `edit {prompt, image, images?, mask?, strength?, size?, n?, out?}` | Edita uma imagem existente no backend ativo (veja os argumentos abaixo). |
| `models {provider?, live?}` | Lista os modelos de cada backend (veja abaixo). |
| `use {provider?, model?, for?}` | Troca o backend e/ou o modelo de imagem da sessão (veja abaixo). |
| `status` | Mostra o backend, o modelo e a região AWS ativos, se ele edita, o backend de edição fixado e quais backends estão configurados. |

**Argumentos do `edit`**
- **`image`:** caminho da imagem de entrada.
- **`images`:** várias imagens de entrada, para modelos que aceitam referências.
- **`mask`:** máscara PNG para inpainting. O branco marca a área a mudar. Uma máscara ilegível faz a edição falhar em vez de repintar a imagem inteira.
- **`strength`:** 0..1, quanto mudar a entrada.

**O que o `models` mostra para cada backend**
- Se o backend está configurado.
- Os modelos que ele oferece **à sua conta agora**. Usa a listagem do próprio provedor quando existe e, caso contrário, o catálogo.
- Para cada modelo: suporte a gen/edit, data de desligamento e, no Bedrock, as regiões.
- `live:false` pula a rede.

**Como o `use` troca**
- **Só o modelo:** o provedor que o serve também é selecionado.
- **Só o provedor:** usa o modelo padrão desse provedor.
- **`for:"edit"`:** fixa o backend usado nas edições quando o ativo não edita.
- **Trocas recusadas:** um provedor sem credencial e um modelo já desligado.

**No coder, é só pedir:**
- "liste os modelos de imagem que eu tenho"
- "use o Gemini para imagens"
- "troque para o Stability SD3.5 no Bedrock"
- "remova o fundo do logo.png"

A IA chama `models`, depois `use`, depois `gen` ou `edit`.

### Marcas de disponibilidade no `@image models`

```text
bedrock — configured
  ✓ stability.stable-image-core-v1:1               gen       (default)  [us-west-2]  Stable Image Core; fastest and cheapest.
  ✓ stability.sd3-5-large-v1:0                     gen+edit  [us-west-2]  SD3.5 Large; image-to-image with strength.
  ✓ stability.stable-image-inpaint-v1:0            edit      [us. profile: us-west-2,us-east-1]  Inpaint …
  ✓ stability.stable-outpaint-v1:0                 unsupported  …  Offered by Bedrock; @image has no request shape for it yet.
```

| Marca | Significado |
|---|---|
| `✓` | A listagem do provedor oferece o modelo à sua conta agora |
| `·` | Vem do catálogo; o provedor não tem listagem ou não está configurado |
| `✗` | A listagem rodou e não oferece o modelo à sua conta |

A listagem tem mais três efeitos:
- **Ids novos aparecem:** um modelo que o provedor lista mas o catálogo ainda não conhece é exibido e pode ser usado.
- **Ids aposentados ficam ocultos:** um id que o catálogo sabe estar desligado fica de fora, mesmo que o provedor ainda o liste.
- **Datas de desligamento valem:** um modelo do catálogo sai da lista no dia do desligamento.

## Edição por provedor

Cada API edita no seu próprio formato de requisição. O `@image edit` roda no backend **ativo**, no contrato desse backend. Um backend que não edita **falha antes de enviar qualquer coisa**. A edição nunca muda em silêncio para outra conta.

| Backend | Gera | **Edita** | Como |
|---|:---:|:---:|---|
| **OpenAI Images** (`gpt-image-2.5-*`, `gpt-image-2`) | ✅ | ✅ | `/images/edits` (multipart), com suporte a máscara |
| **OpenAI Responses** (`gpt-5.6-*`, `gpt-5.5`, `gpt-5.4-mini`) | ✅ | ✅ | na mesma chamada `/responses`: `input_image` + `image_generation` com `action: "edit"` |
| **Google** (Gemini / Nano Banana) | ✅ | ✅ | `:generateContent` com imagem(ns) inline |
| **xAI** (Grok Imagine) | ✅ | ✅ | `/images/edits` em JSON: a entrada vai como data URI em `image.url` (`images[]` para várias); sem `size`; a URL do resultado é baixada |
| **Bedrock** | por modelo | por modelo | veja a próxima seção |
| **SD WebUI** | ✅ | ✅ | img2img, keyless e local |
| **Self-hosted** (`CHATCLI_IMAGE_URL`) | ✅ | ✅ / ❌ | `/images/edits` multipart; `CHATCLI_IMAGE_URL_EDITS=false` se o servidor só gera |
| Z.AI (GLM-Image / CogView) | ✅ | ❌ | a API só gera |
| MiniMax (Image-01) | ✅ | ❌ | a API só gera |

### Bedrock: regiões, profiles e modelos

Hoje, geração de imagem no Bedrock significa apenas modelos **Stability**. **O Nova Canvas chegou ao fim da vida em 30/09/2026**, e o Titan Image não existe mais. O que muda de um modelo para outro é onde ele roda e se precisa de profile.

**Geração e image-to-image: `stability.stable-image-core-v1:1`, `stability.stable-image-ultra-v1:1`, `stability.sd3-5-large-v1:0`.**
- São oferecidos **só em `us-west-2`**, In-Region.
- O chatcli os invoca lá mesmo quando `AWS_REGION` ou `BEDROCK_REGION` aponta para outra região.
- Era essa divergência que falhava com `The provided model identifier is invalid`.
- O Core só gera. Ultra e SD3.5 Large também editam (`strength`).

**Image Services: inpaint, erase object, remove background, control sketch, control structure, style guide e upscale creative, conservative e fast.**
- Recebem uma imagem de entrada (sem text-to-image) e rodam **só pelo profile cross-region US**.
- O chatcli adiciona o prefixo `us.` sozinho e os invoca a partir de us-east-1, us-east-2 ou us-west-2.
- **Inpaint** e **erase object** usam a `mask`.
- **Remove background**, **erase object** e **fast upscale** ignoram o prompt.
- `strength` vira control strength (modelos control), fidelity (style guide) ou creativity (creative upscale, no máximo 0.35).

| Modelo Bedrock | Gera | Edita | Região / profile |
|---|:---:|:---:|---|
| `stability.stable-image-core-v1:1` (padrão) | ✅ | ❌ | us-west-2 |
| `stability.stable-image-ultra-v1:1` | ✅ | ✅ | us-west-2 |
| `stability.sd3-5-large-v1:0` | ✅ | ✅ | us-west-2 |
| `stability.stable-image-inpaint-v1:0` | ❌ | ✅ | profile `us.` |
| `stability.stable-image-erase-object-v1:0` | ❌ | ✅ | profile `us.` |
| `stability.stable-image-remove-background-v1:0` | ❌ | ✅ | profile `us.` |
| `stability.stable-image-control-sketch-v1:0` / `-control-structure-v1:0` | ❌ | ✅ | profile `us.` |
| `stability.stable-image-style-guide-v1:0` | ❌ | ✅ | profile `us.` |
| `stability.stable-creative-upscale-v1:0` / `-conservative-upscale-v1:0` / `-fast-upscale-v1:0` | ❌ | ✅ | profile `us.` |

O `@image models` também lista os modelos Bedrock que o `@image` ainda não aciona, marcados como `unsupported`: search-and-replace, search-and-recolor, outpaint e style transfer.

**Os erros do Bedrock agora dizem o que fazer:**
- Região errada: o erro diz onde o modelo existe.
- Profile ausente: o erro diz o id `us.` a usar.
- Sem acesso ao modelo: o erro aponta para o console do Bedrock.

## Editar em outro backend: só quando você fixa

Quando o backend ativo não edita, o `@image edit` não envia nenhuma requisição. Ele devolve um erro claro com o backend e o modelo, por exemplo Z.AI `glm-image` ou Bedrock `stable-image-core`. Ter chave de outros provedores **não** leva a edição para eles.

Para editar num backend diferente do que gera, fixe-o. A IA pode fazer isso com `@image use {"provider":"xai","for":"edit"}`, ou você mesmo pode definir:

```bash
export CHATCLI_IMAGE_PROVIDER=zai            # gera com GLM-Image
export CHATCLI_IMAGE_EDIT_PROVIDER=sdwebui   # edita no SD WebUI local (keyless)
export CHATCLI_IMAGE_EDIT_MODEL=             # modelo opcional do backend de edição
```

A resposta então avisa:

> ℹ️ O backend de imagem `"zai"` não edita imagens; esta edição rodou em `"sdwebui"`, como fixa CHATCLI_IMAGE_EDIT_PROVIDER.

- `CHATCLI_IMAGE_EDIT_PROVIDER` aceita `sdwebui`, `url`, `openai`, `responses`, `google`, `xai`, `zai`, `minimax`, `bedrock`.
- Só é usado quando o backend ativo não edita.
- Se o backend fixado também não editar (chave ausente ou modelo que só gera), o erro diz isso também.

## Comandos

```text
@image models                                  # por backend, ao vivo onde o provider lista modelos
/model-image gemini-nano-banana-2.1            # modelo + o provider que o serve (gera e edita)
/config image                                  # panorama (backend, api, modelo, url, backend de edição)
/config image models                           # mesma listagem do @image models
/config image model stability.sd3-5-large-v1:0 # mesmo que /model-image
/config image edit xai                         # backend usado nas edições quando o ativo não edita
/config image provider responses               # fixa um backend
/config image api responses                    # OpenAI: Images ou Responses
/config image reset                            # limpa todos os overrides acima
```

- `/model-image`, `/config image model` e `@image use` selecionam o **backend que serve o modelo**. Por isso, escolher um modelo Gemini com o provedor fixado na xAI troca para o Google, em vez de mandar um id Gemini para a xAI.
- Essas trocas valem para a sessão. Para manter uma delas, defina `CHATCLI_IMAGE_PROVIDER`/`CHATCLI_IMAGE_MODEL` (ou `CHATCLI_IMAGE_EDIT_PROVIDER`/`CHATCLI_IMAGE_EDIT_MODEL`) no `.env`.

## Formatos & detalhes

- **OpenAI edits** aceita `image/jpeg`, `image/png` e `image/webp` (não `gif`). O `Content-Type` do part multipart vem dos bytes da imagem.
- **SD WebUI img2img** mapeia `strength` para `denoising_strength`. O padrão é `0.6`: uma mudança visível que preserva a estrutura.
- **Bedrock Stability:**
  - text-to-image envia um `aspect_ratio`;
  - o SD3.5 Large edita com `mode: image-to-image` + `strength`;
  - o Ultra edita com `image` + `strength`;
  - os Image Services enviam os campos que cada um aceita.

## Privacidade & custo

- O **Stable Diffusion WebUI local** é keyless e gera **e** edita na sua máquina. É a opção privada e de custo zero.
- Backends de nuvem usam as chaves **do próprio usuário**.
- Confirme antes de gerar ou editar lotes grandes e mencione o custo quando fizer diferença.
