O ChatCLI suporta um sistema de plugins para estender suas funcionalidades. Um plugin é um **executável** que segue um contrato específico, permitindo que o ChatCLI o descubra, execute e interaja com ele de forma segura.

Isso permite criar comandos customizados (como `@kind`, `@deploy`) que podem orquestrar ferramentas, interagir com APIs ou realizar qualquer lógica que você possa programar.

<Info>
**Plugin de tool ou plugin de provider?** Esta página trata de **plugins de tool**: comandos que o modelo chama durante uma conversa. Para adicionar um **provider de LLM** inteiro — um gateway corporativo ou um SDK interno com que o ChatCLI conversa no lugar de um fornecedor embutido — veja [Plugins de Provider](/pt/extensions/provider-plugins).
</Info>

## Para Usuários: Gerenciando Plugins

### Listar plugins instalados

```bash
/plugin list
```

Mostra todos os comandos de plugin disponíveis, incluindo plugins `[builtin]` (como `@coder`) e `[remote]` (de servidores conectados).

### Instalar um plugin

Instale diretamente de um repositório Git:

```bash
/plugin install https://github.com/usuário/meu-plugin-chatcli.git
```

O ChatCLI irá clonar, compilar (se for Go) e instalar o executável em `~/.chatcli/plugins/`, assinado com a chave local desta máquina para carregar com a exigência de assinatura ligada.

Ou instale um binário pronto e assinado — do disco ou da URL de uma release:

```bash
/plugin install ./acme-tool
/plugin install --binary https://releases.example.com/acme-tool
```

A primeira instalação de um publicador pede que você confirme o fingerprint da chave uma vez; veja [Verificação de Assinatura](#verificação-de-assinatura).

<Warning>
**Segurança:** A instalação de um plugin envolve baixar e executar código de terceiros. Instale plugins apenas de fontes que você confia.
</Warning>

### Ver detalhes de um plugin

```bash
/plugin show <nome-do-plugin>
```

### Desinstalar um plugin

```bash
/plugin uninstall <nome-do-plugin>
```

### Recarregar plugins

O ChatCLI monitora automaticamente `~/.chatcli/plugins/` e **recarrega quando detecta mudanças** (criação, remoção, modificação). Um debounce de 500ms evita recarregamentos múltiplos.

Para forçar um recarregamento manual:

```bash
/plugin reload
```

<Tip>
Desenvolva plugins iterativamente: edite o código, recompile, envie ao diretório de plugins — o ChatCLI detectará a mudança automaticamente.
</Tip>

## Para Desenvolvedores: Criando um Plugin

### O contrato do plugin

1. **Executável** — O plugin deve ser um arquivo executável (qualquer linguagem)
2. **Localização** — Colocado em `~/.chatcli/plugins/`
3. **Nome do comando** — O nome do arquivo vira o comando. Ex: arquivo `kind` = comando `@kind`
4. **Metadados (`--metadata`)** — Obrigatório. O executável deve responder a está flag com JSON:

```json
{
  "name": "@meu-comando",
  "description": "Uma breve descrição do que o plugin faz.",
  "usage": "@meu-comando <subcomando> [--flag value]",
  "version": "1.0.0"
}
```

5. **Schema (`--schema`)** — Opcional. Descreve os parâmetros aceitos:

```json
{
  "parameters": [
    {
      "name": "cluster-name",
      "type": "string",
      "required": true,
      "description": "Nome do cluster Kubernetes"
    }
  ]
}
```

6. **Comunicação (stdout vs stderr)**:
   - **stdout** — Apenas o resultado final (retornado ao ChatCLI/IA)
   - **stderr** — Logs de progresso, status e avisos (exibidos em tempo real ao usuário)

---

### Exemplo: Plugin "Hello World" em Go

```go
package main

import (
    "encoding/json"
    "flag"
    "fmt"
    "os"
    "time"
)

type Metadata struct {
    Name        string `json:"name"`
    Description string `json:"description"`
    Usage       string `json:"usage"`
    Version     string `json:"version"`
}

// logf envia mensagens de progresso para o usuário (via stderr).
func logf(format string, v ...interface{}) {
    fmt.Fprintf(os.Stderr, format, v...)
}

func main() {
    metadataFlag := flag.Bool("metadata", false, "Exibe os metadados do plugin")
    schemaFlag := flag.Bool("schema", false, "Exibe o schema de parâmetros")
    flag.Parse()

    if *metadataFlag {
        meta := Metadata{
            Name:        "@hello",
            Description: "Plugin de exemplo que demonstra o fluxo stdout/stderr.",
            Usage:       "@hello [seu-nome]",
            Version:     "1.0.0",
        }
        jsonMeta, _ := json.Marshal(meta)
        fmt.Println(string(jsonMeta))
        return
    }

    if *schemaFlag {
        schema := map[string]interface{}{
            "parameters": []map[string]interface{}{
                {
                    "name":        "nome",
                    "type":        "string",
                    "required":    false,
                    "description": "Nome da pessoa a ser cumprimentada",
                    "default":     "Mundo",
                },
            },
        }
        jsonSchema, _ := json.Marshal(schema)
        fmt.Println(string(jsonSchema))
        return
    }

    // Lógica principal
    logf("Plugin 'hello' iniciado!\n")
    time.Sleep(2 * time.Second)
    logf("   - Realizando uma tarefa demorada...\n")
    time.Sleep(2 * time.Second)

    name := "Mundo"
    if len(flag.Args()) > 0 {
        name = flag.Args()[0]
    }

    logf("Tarefa concluída!\n")

    // Resultado final vai para stdout
    fmt.Printf("Olá, %s! A hora agora é %s.", name, time.Now().Format(time.RFC1123))
}
```

### Compilação e instalação

```bash
# 1. Compilar
go build -o hello ./hello/main.go

# 2. Dar permissão de execução
chmod +x hello

# 3. Criar diretório de plugins (se não existir)
mkdir -p ~/.chatcli/plugins/

# 4. Mover o executável
mv hello ~/.chatcli/plugins/

# 5. Usar no ChatCLI
/agent Olá meu nome é Fulano
```

## Capability Interfaces (Opt-in)

Plugins podem expor capabilities através de interfaces Go opcionais. Plugins legados que não implementam continuam funcionando — todas as interfaces são fail-closed (default conservador). Implementando, o plugin participa de otimizações do orquestrador:

| Interface | Método | Para que serve |
|---|---|---|
| `ReadOnlyAware` | `IsReadOnly(args []string) bool` | Habilita capability gate (security auto-allow) e participa de batches paralelos |
| `ConcurrencySafeAware` | `IsConcurrencySafe(args []string) bool` | Sinaliza que múltiplas chamadas podem rodar em paralelo |
| `DescriberWithInput` | `DescribeCall(args []string) string` | Label dinâmico no spinner ("Reading: main.go" em vez de "EXECUTANDO: @read") |
| `JSONSchemaAware` | `JSONSchema() string` | Schema draft-2020-12 validado antes do dispatch — input inválido vira `ToolResult{IsError:true, ErrorCode:"InvalidArgs"}` |
| `TruncationAware` | `MaxResultChars() int` | Per-tool cap de output (versus o global de 30 000) |
| `Prompter` | `Prompt(opts PromptOpts) (string, error)` | Slice do system prompt contextual |
| `StreamingInputAware` | `UpdateStreamingInput(field, value string)` | Eventos de input parcial enquanto o LLM streama args |
| `StructuredExecutor` | `ExecuteStructured(...) (StructuredResult, error)` | Retorno tipado em vez do `(string, error)` legado |

Exemplo — um plugin que quer auto-allow + paralelização + label customizado:

```go
func (p *MyReadOnlyPlugin) IsReadOnly(_ []string) bool        { return true }
func (p *MyReadOnlyPlugin) IsConcurrencySafe(_ []string) bool { return true }
func (p *MyReadOnlyPlugin) DescribeCall(args []string) string {
    return i18n.T("plugins.myplugin.describe", extractTarget(args))
}
func (p *MyReadOnlyPlugin) JSONSchema() string {
    return `{"type":"object","properties":{"file":{"type":"string"}},"required":["file"]}`
}
```

Os 4 plugins atômicos (`@read`, `@search`, `@tree`, `@todo`) — veja [Tools Atômicos](/pt/coder/atomic-tools) — usam todas as capabilities relevantes como exemplo de referência.

## Verificação de Assinatura

Um plugin só roda quando está assinado por uma chave em que esta máquina confia: uma assinatura Ed25519 sobre o SHA-256 do binário, num `<plugin>.sig` separado, ao lado dele. A chave pública do publicador pode acompanhar o plugin como `<plugin>.pub`, mas **uma chave que vem no pacote nunca é confiável por si só** — qualquer pessoa pode assinar um binário com a própria chave e mandar essa chave junto, então confiar nela automaticamente faria a assinatura não provar nada. Uma chave passa a ser confiável por uma decisão tomada fora do pacote, de uma de três formas:

<CardGroup cols={3}>
  <Card title="Confiança no primeiro uso" icon="fingerprint">
    A primeira instalação de um publicador mostra o fingerprint da chave e pergunta uma vez. A chave passa a ser confiável e fica **fixada** naquele plugin: atualizações instalam sem perguntar, uma chave diferente é recusada.
  </Card>
  <Card title="Chaves gerenciadas" icon="building-shield">
    Um administrador coloca a chave do publicador ao lado do `managed.env`. Todo usuário da máquina confia nela, sem copiar nada.
  </Card>
  <Card title="Compilado do código-fonte" icon="hammer">
    O `/plugin install <url-git>` compila na sua máquina depois que você confirma, e assina o resultado com a chave própria desta máquina.
  </Card>
</CardGroup>

### Instalar um plugin assinado

```bash
/plugin install ./acme-tool                                   # REPL: um binário pronto no disco
/plugin install --binary https://releases.example.com/acme-tool
chatcli plugin install https://releases.example.com/acme-tool  # fora do REPL
```

O ChatCLI baixa `<origem>`, `<origem>.sig` e `<origem>.pub` (só https), confere tudo e não grava nada no diretório de plugins até o publicador ser confiável:

| O pacote | O que acontece |
| --- | --- |
| Assinado por uma chave em que você ou seu administrador já confiam | Instala |
| Assinado por um publicador desconhecido, com a chave no pacote | Mostra o fingerprint e pergunta uma vez; se você aceitar, a chave passa a ser confiável e fica fixada no plugin |
| O mesmo, sem uma pessoa no terminal (CI, scripts) | Recusado, informando o fingerprint — repita com `--trust SHA256:…` |
| Mesmo plugin, assinado por uma chave diferente da fixada | Recusado, mesmo que você confirmasse. Se o publicador trocou mesmo de chave, desinstale o plugin e instale de novo |
| A assinatura não confere com a chave do pacote nem com nenhuma chave confiável | Recusado: o binário ou a assinatura foi alterado |
| Não assinado | Recusado, a menos que `CHATCLI_ALLOW_UNSIGNED_PLUGINS=true` |

<Tip>
Compare o fingerprint que o ChatCLI mostra com o que o publicador divulga — na página da release ou no portal interno — antes de confiar. É essa comparação que torna segura a confiança no primeiro uso.
</Tip>

### Publicar um plugin assinado

<Steps>
  <Step title="Gere a chave do publicador uma vez">
    ```bash
    chatcli plugin keygen --output ~/acme-signing
    # plugin-signing.key (0600, mantenha em segredo) e plugin-signing.pub,
    # mais o fingerprint a divulgar: SHA256:…
    ```
  </Step>
  <Step title="Assine cada release">
    ```bash
    chatcli plugin sign --binary dist/acme-tool --key ~/acme-signing/plugin-signing.key
    # grava dist/acme-tool.sig
    ```
  </Step>
  <Step title="Publique o pacote e divulgue o fingerprint">
    Publique `acme-tool`, `acme-tool.sig` e a chave pública renomeada para `acme-tool.pub`, lado a lado, e mostre o fingerprint onde os usuários baixam o plugin.
  </Step>
</Steps>

### Chaves gerenciadas para organizações

Coloque o `.pub` do publicador no diretório de chaves gerenciadas, ao lado do `managed.env`:

| Sistema | Diretório |
| --- | --- |
| macOS, Linux | `/etc/chatcli/trusted-keys/` |
| Windows | `%ProgramData%\chatcli\trusted-keys\` |

A partir daí, todo usuário da máquina confia nesse publicador, inclusive quem nunca criou um diretório de chaves próprio. O diretório pertence ao administrador, então um usuário não consegue remover a chave.

### Plugins compilados do código-fonte

O `/plugin install <url-git>` clona e compila o plugin na sua máquina depois que você confirma a instalação. O binário resultante é assinado com uma chave local da máquina — criada em `~/.chatcli/local-signing/` no primeiro uso e confiável como `local-machine` —, então ele carrega com a exigência de assinatura ligada, sem passo de keygen ou de trust.

### Inspecionar e gerenciar a confiança

```bash
chatcli plugin trust list                          # chaves confiáveis (do usuário e gerenciadas) e publicadores fixados
chatcli plugin trust --key ./publisher.pub         # confiar numa chave manualmente
chatcli plugin verify --binary ~/.chatcli/plugins/acme-tool
```

```text
Chaves confiáveis:

  acme                             SHA256:qVrckaw/nhbU80swrHGK9e7icHuwzZE3MkfGQlm3m+A  (managed)
Publicadores fixados:
  tool:acme-tool                   SHA256:qVrckaw/nhbU80swrHGK9e7icHuwzZE3MkfGQlm3m+A
```

### Permissões de Arquivo

O diretório de plugins usa permissões **0o700** (somente o dono pode ler, escrever e executar). O ChatCLI verifica as permissões na inicialização e emite um aviso se estiverem mais permissivas.

### Modo de Desenvolvimento

Para desenvolvimento local, é possível desabilitar a verificação de assinatura:

```bash
export CHATCLI_ALLOW_UNSIGNED_PLUGINS=true
chatcli
```

<Warning>
**Nunca** habilite `CHATCLI_ALLOW_UNSIGNED_PLUGINS` em produção. Plugins não assinados podem executar código arbitrário com as permissões do processo ChatCLI.
</Warning>

## Plugins Remotos

Ao conectar a um servidor via `chatcli connect`, plugins do servidor são descobertos automaticamente:

- Aparecem em `/plugin list` com a tag `[remote]`
- São executados no servidor (não baixados localmente por padrão)
- Plugins locais e remotos coexistem sem conflito
