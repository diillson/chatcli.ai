---
title: "Approve Request"
openapi: "POST /approvals/{name}/approve"
description: "Approves an approval request, allowing the remediation to be executed"
icon: "circle-check"
---

<ParamField path="name" type="string" required>
  Approval request name (e.g., `approval-payment-service-oom-kill-1773933600-plan-1`)
</ParamField>

<ParamField query="namespace" type="string">
  Kubernetes namespace. When omitted, every namespace is searched (first match).
</ParamField>

<ParamField body="approver" type="string" required>
  Name of the person approving, recorded next to the identity of the API key. An empty value returns `400`.
</ParamField>

<ParamField body="reason" type="string">
  Optional justification
</ParamField>

The call records **one decision** on a `Pending` request, the same way the `platform.chatcli.io/approve` annotation does: it appends an entry to `status.decisions` with the approver, the reason and a timestamp. It never sets `status.state` itself. The ApprovalReconciler then evaluates the decisions against the rule: once the required approvals are in (one for `manual`, `requiredApprovers` distinct approvers for `quorum`) and the change window is open, the request becomes `Approved` and the RemediationPlan waiting on it moves to `Executing`. The response is returned right after the decision is recorded, so it usually still shows `Pending`, with the new entry in `decisions` and in `approvedBy`. The item is returned in `spec` and `status` alike, plus `resourceMeta`.

- **Approver identity.** The approver is stored as `<approver> (api-key: <identity>)`, where the identity is the `name` of the API key entry, else its `description`, else a `key-<hash>` fingerprint (`dev-mode` in dev mode). The typed name is trimmed, control characters are dropped, and it is cut at 128 characters.
- **Quorum counts API keys.** Two approvals made with the same key count once, whatever names are typed, and the same key cannot decide twice on a request. A shared key, or dev mode, cannot satisfy `requiredApprovers: 2`: give each approver their own key.
- **`409`** when the request is no longer `Pending` (already approved, rejected or expired), or when the same key already recorded a decision on it.
- **Change window.** An approval recorded outside the rule's window is kept; the request turns `Approved` when the window opens and does not expire while it waits. See [Approval Workflow](/kubernetes/aiops/approval-workflow#changewindowspec).
