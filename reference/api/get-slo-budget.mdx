---
title: "Get SLO Error Budget"
openapi: "GET /slos/{name}/budget"
description: "Returns the error budget numbers of an SLO"
icon: "coins"
---

<ParamField path="name" type="string" required>
  SLO name (e.g., `payment-availability`)
</ParamField>

<ParamField query="namespace" type="string">
  Namespace of the SLO. When omitted, every namespace is searched.
</ParamField>

Minimum role: `viewer`. The response has only `spec` (no `status` or `resourceMeta`) and every field is always present. There is no history, forecast or granularity option.

- `currentValue` and `errorBudgetRemaining` are percentages; `errorBudgetTotal` is a fraction (`1 - target/100`).
- `burnRate` is computed here as `errorBudgetUsed / errorBudgetTotal`, a ratio, not a time-windowed burn rate. Because the SLO controller does not write `status.errorBudgetUsed` in the current release, `errorBudgetUsed` and `burnRate` are `0` and `state` is empty. The controller's multi-window burn rates are on the resource itself: `kubectl get slo <name> -o jsonpath='{.status.burnRate1h}'` (also `burnRate6h`, `burnRate24h`, `burnRate72h`).
