---
title: "List Approvals"
openapi: "GET /approvals"
description: "Returns the list of pending and historical approval requests"
icon: "list"
---

<ParamField query="state" type="string">
  Filter by state (exact match): `Pending`, `Approved`, `Rejected`, `Expired`
</ParamField>

<ParamField query="namespace" type="string">
  Filter by namespace (omit for all namespaces)
</ParamField>

<ParamField query="page" type="integer" default="1">
  Page number
</ParamField>

<ParamField query="pageSize" type="integer" default="20">
  Items per page (maximum 100)
</ParamField>

Each item is an `ApprovalRequest` custom resource projected into a flat shape:

| Field | Source |
|:------|:-------|
| `name` | `approval-<remediation plan>` for remediation approvals (`chaos-<experiment>` for chaos experiments) |
| `resource` | Name of the Issue the approval is for (`spec.issueRef.name`) — despite the field name, not a workload |
| `action` | Type of the **first** requested action (`spec.requestedActions[0].type`) |
| `reason` | The policy that required the approval (`spec.policyRef`): an ApprovalPolicy name, or `decision-engine` / `cluster-tier` for requests raised by the operator itself |
| `requestedBy` | `spec.requester` (`chatcli-operator` for requests the operator creates) |
| `state` | `Pending`, `Approved`, `Rejected` or `Expired`; an empty status is reported as `Pending` |
| `approvedBy`, `rejectedBy`, `decisionReason` | Derived from `status.decisions`: the approvers who approved or rejected (comma-separated) and the reason of the decision |
| `decidedAt` | `status.approvedAt`, `rejectedAt` or `expiredAt`, once the request is finished |
| `requiredApprovers` | `spec.requiredApprovers`: distinct approvers a `quorum` rule needs |
| `decisions` | `status.decisions[]`: `approver`, `decision` (`approved`/`rejected`), `reason`, `timestamp`. A REST or dashboard approver reads `<name> (api-key: <identity>)` (see [Approve Request](/reference/api/approve)) |
| `labels`, `annotations` | The ApprovalRequest's labels and annotations. The blast radius prediction is in the annotations `platform.chatcli.io/blast-radius` and `platform.chatcli.io/blast-risk-level` (the dashboard's blast-radius badge reads them) |

The AI evidence and timeout are not part of this projection; read them from the resource with `kubectl get approvalrequest <name> -o yaml`.
