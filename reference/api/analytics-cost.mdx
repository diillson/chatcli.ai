---
title: "Analytics Cost"
openapi: "GET /analytics/cost"
description: "Returns the LLM spend the controllers booked per incident — total cost, incident count and cost per incident for a namespace and window"
icon: "coins"
---

<ParamField query="namespace" type="string">
  Kubernetes namespace whose ledger to read. Empty aggregates every namespace's ledger.
</ParamField>

<ParamField query="from" type="string">
  Start of the window, RFC 3339
</ParamField>

<ParamField query="to" type="string">
  End of the window, RFC 3339. `from` and `to` are an absolute period: with both, exactly `[from, to]`; with only `from`, it runs to now; with only `to`, the 30 days ending at `to`; with neither, the last 30 days.
</ParamField>

## Summary Fields

| Field | Description |
|-------|-------------|
| `periodStart` / `periodEnd` | Period boundaries (`periodEnd` is `to`, or the request time without it) |
| `totalLLMCost` | Sum of every incident's `estimatedCostUSD` booked inside the window (entries without a `recordedAt`, written before the stamp existed, always count) |
| `incidentCount` | Incidents with a ledger entry in the window |
| `costPerIncident` | `totalLLMCost / incidentCount` |

Minimum role: `viewer`. A namespace with no `chatcli-cost-ledger` yet answers `200` with zero totals; any other failure to read the ledger returns `500` (`failed to read the cost ledger: ...`) instead of zeros. Each LLM call is priced at its own model's rate when it is booked and added to the incident's total, and concurrent bookings retry on conflict, so none is lost. There is no ROI, downtime-cost or per-incident breakdown in the response.

The ledger lives in one `chatcli-cost-ledger` ConfigMap per namespace (found by the label `app.kubernetes.io/managed-by: chatcli-operator` when aggregating); see [Capacity, Noise and Cost](/kubernetes/aiops/capacity-cost#cost-tracker) for its format and the pricing override.
