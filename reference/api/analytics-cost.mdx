---
title: "Analytics Cost"
openapi: "GET /analytics/cost"
description: "Returns the LLM spend the controllers booked per incident — total cost, incident count and cost per incident for a namespace and window"
icon: "coins"
---

<ParamField query="namespace" type="string">
  Kubernetes namespace whose ledger to read. Empty aggregates every namespace's ledger.
</ParamField>

<ParamField query="from" type="string">
  Start of the window, RFC 3339
</ParamField>

<ParamField query="to" type="string">
  End of the window, RFC 3339. The window **length** is `to − from` when both are valid, otherwise 30 days; the window always ends at the current time (`periodEnd` is now).
</ParamField>

## Summary Fields

| Field | Description |
|-------|-------------|
| `periodStart` / `periodEnd` | Window boundaries (`periodEnd` is always the request time) |
| `totalLLMCost` | Sum of every incident's `estimatedCostUSD` booked inside the window (entries without a `recordedAt`, written before the stamp existed, always count) |
| `incidentCount` | Incidents with a ledger entry in the window |
| `costPerIncident` | `totalLLMCost / incidentCount` |

Minimum role: `viewer`. If the ledger cannot be read (for example, no `chatcli-cost-ledger` exists in that namespace yet), the endpoint still answers `200` with zero totals. There is no ROI, downtime-cost or per-incident breakdown in the response.

The ledger lives in one `chatcli-cost-ledger` ConfigMap per namespace (found by the label `app.kubernetes.io/managed-by: chatcli-operator` when aggregating); see [Capacity, Noise and Cost](/features/aiops/capacity-cost#cost-tracker) for its format and the pricing override.
