openapi: "POST /postmortems/{name}/review"
description: "Moves a postmortem to InReview state, indicating a human is reviewing the AI-generated analysis"
icon: "user-pen"
---

<ParamField path="name" type="string" required>
  PostMortem name (e.g., `pm-checkout-service-oom-kill-1773871200`)
</ParamField>

<ParamField query="namespace" type="string" default="default">
  Kubernetes namespace (only `default` is searched when omitted)
</ParamField>

<ParamField body="reviewer" type="string">
  Identifier of the reviewer (e.g., a username). Stored in the annotation `aiops.chatcli.io/reviewed-by`.
</ParamField>

<ParamField body="notes" type="string">
  Review notes. Stored in the annotation `aiops.chatcli.io/review-notes`, and **only when `reviewer` is also sent**.
</ParamField>

## When to Use

PostMortems are generated when an incident is resolved or contained. This endpoint lets the team:

1. **Mark it as under review**: sets `status.state` to `InReview` and `status.reviewedAt` to the current time
2. **Record who is reviewing**: the optional `reviewer`/`notes` land as annotations on the PostMortem
3. **Tell reviewed from unreviewed postmortems**: `Open` means nobody has looked at it yet

The body is optional. The endpoint does not change the root cause, timeline or other analysis fields; use [Developer Feedback](/reference/api/feedback-postmortem) to record a corrected root cause. Minimum role: `operator`. There is no state guard: the call also works on a `Closed` postmortem and moves it back to `InReview`.
