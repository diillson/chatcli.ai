---
title: "List Incidents"
openapi: "GET /incidents"
description: "Returns a list of incidents (Issue resources) with optional filters and pagination"
icon: "list"
---

Each item is an `Issue` custom resource projected into the incident shape below. Filters are exact matches and are combined with AND.

<ParamField query="namespace" type="string">
  Only incidents in this Kubernetes namespace. Omit to list every namespace.
</ParamField>

<ParamField query="severity" type="string">
  Filter by severity: `critical`, `high`, `medium`, `low`
</ParamField>

<ParamField query="state" type="string">
  Filter by state: `Detected`, `Analyzing`, `Remediating`, `Contained`, `Resolved`, `Escalated`, `Failed`
</ParamField>

<ParamField query="from" type="string">
  Only incidents created at or after this RFC 3339 time (e.g., `2026-03-19T00:00:00Z`)
</ParamField>

<ParamField query="to" type="string">
  Only incidents created at or before this RFC 3339 time
</ParamField>

<ParamField query="page" type="integer" default="1">
  Page number
</ParamField>

<ParamField query="pageSize" type="integer" default="20">
  Items per page (maximum 100)
</ParamField>

<Note>
`requiresHumanAction` is `true` when the incident is `Contained` (the operator silenced the workload and a person must restore it) and `requiredAction` says what to do. `chaosInduced` / `chaosExperiment` are set when the incident was correlated with an active ChaosExperiment. Empty optional fields are omitted.
</Note>
