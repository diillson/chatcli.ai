---
title: "List Policies"
openapi: "GET /policies/{kind}"
description: "Lists ApprovalPolicy, NotificationPolicy, EscalationPolicy or IncidentSLA objects with their raw spec and status — read-only"
icon: "list-check"
---

<ParamField path="kind" type="string" required>
  `approval`, `notification`, `escalation` or `sla`
</ParamField>

<ParamField query="namespace" type="string">
  Filter by namespace. Empty lists every namespace.
</ParamField>

<ParamField query="page" type="integer" default="1">
  Page number
</ParamField>

<ParamField query="pageSize" type="integer" default="20">
  Items per page
</ParamField>

Policies are written through `kubectl` or GitOps, where they are reviewed; the API and the dashboard's Policies tab only read them. Each item carries the CRD `spec` and `status` unchanged, so the fields follow the [ApprovalPolicy](/features/aiops/approval-workflow), [NotificationPolicy and EscalationPolicy](/features/aiops/notifications) and [IncidentSLA](/features/aiops/slo-sla) definitions.

<ResponseExample>
```json Response 200
{
  "apiVersion": "v1",
  "kind": "ApprovalPolicyList",
  "metadata": { "totalCount": 1, "page": 1, "pageSize": 20 },
  "items": [
    {
      "name": "prod-rollbacks",
      "namespace": "production",
      "kind": "ApprovalPolicy",
      "creationTimestamp": "2026-09-01T12:00:00Z",
      "spec": {
        "enabled": true,
        "rules": [
          { "name": "rollback-requires-human", "match": { "actionTypes": ["RollbackDeployment"] }, "mode": "manual", "timeoutMinutes": 30, "requiredApprovers": 1 }
        ]
      },
      "status": { "totalApproved": 7, "totalRejected": 1 }
    }
  ]
}
```
</ResponseExample>
