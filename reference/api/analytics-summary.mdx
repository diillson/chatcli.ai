---
title: "Analytics Summary"
openapi: "GET /analytics/summary"
description: "Returns a consolidated summary of operational metrics from the platform"
icon: "chart-line"
---

<ParamField query="from" type="string">
  Start of the window, RFC 3339 (e.g., `2026-03-01T00:00:00Z`). An unparseable value is ignored.
</ParamField>

<ParamField query="to" type="string">
  End of the window, RFC 3339.
</ParamField>

Minimum role: `viewer`. Without `from`/`to`, every resource in the cluster is counted. There are no `period`, `namespace` or `cluster` filters: the summary always covers all namespaces of the cluster the operator runs in.

What the window applies to:

- Issues, RemediationPlans and PostMortems are filtered by `creationTimestamp`.
- `totalRunbooks`, `totalSLOs`, `slosAtRisk` and `pendingApprovals` are **not** time filtered (current totals).

Field notes:

- `openIssues` counts every Issue that is not `Resolved` (including `Contained`, `Escalated` and `Failed`); `containedIssues` is also counted in `openIssues`.
- `successfulRemediations` are plans in state `Completed`; `failedRemediations` are `Failed` or `RolledBack`.
- `remediatedIssues` is the number of distinct Issues with at least one plan in the window, and `resolvedByRemediation` how many of those ended `Resolved`.
- `chaosInducedIssues` counts Issues labeled `platform.chatcli.io/source: chaos-experiment`.
- `pendingApprovals` counts ApprovalRequests whose state is `Pending` or empty.
- `slosAtRisk` looks for `status.state` `AtRisk` or `Breached` on SLOs, a field the SLO controller does not write in the current release, so it stays `0`.
