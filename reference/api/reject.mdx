---
title: "Reject Request"
openapi: "POST /approvals/{name}/reject"
description: "Rejects an approval request, preventing the remediation from being executed"
icon: "circle-xmark"
---

<ParamField path="name" type="string" required>
  Approval request name (e.g., `approval-payment-service-oom-kill-1773933600-plan-1`)
</ParamField>

<ParamField query="namespace" type="string">
  Kubernetes namespace. When omitted, every namespace is searched (first match).
</ParamField>

<ParamField body="approver" type="string" required>
  Who is rejecting the request. An empty value returns `400`.
</ParamField>

<ParamField body="reason" type="string">
  Reason for the rejection
</ParamField>

The call sets the request's `status.state` to `Rejected`; the operator then reacts to the new state: the RemediationPlan waiting on it is marked `Failed` with the result `Approval rejected by : ` (empty approver and reason, see below). The response contains the updated item in `spec` and `resourceMeta` (no `status`).

<Warning>
**Limitations of the REST decision (current release):**

- **The approver and reason are not stored.** The handler also writes `status.rejectedBy`, `status.decisionReason` and `status.decidedAt`, but the ApprovalRequest CRD does not define these fields, so the Kubernetes API server drops them. Only the state change persists; the response and later GETs show them empty, and no entry is added to `status.decisions`.
- **No state or expiry check.** The request is not required to be `Pending`: an already decided or `Expired` request is overwritten, and there is no `409`/`410`.
- **Quorum is bypassed.** A single call decides the request even when its rule requires several approvers.

To record who decided and why (and to go through the controller's own decision path, including quorum), annotate the ApprovalRequest instead:

```bash
kubectl -n production annotate approvalrequest approval-payment-service-oom-kill-1773933600-plan-1 \
  platform.chatcli.io/reject="oncall-sre:prefer tuning the HPA first"
```

The value is `<approver>:<reason>`; the controller appends it to `status.decisions` and removes the annotation.
</Warning>
