---
title: "Snooze Incident"
openapi: "POST /incidents/{name}/snooze"
description: "Holds an incident's notifications and escalation for a period"
icon: "clock"
---

<ParamField path="name" type="string" required>
  Name of the Issue resource (e.g., `payment-service-oom-kill-1773933600`)
</ParamField>

<ParamField query="namespace" type="string">
  Namespace of the incident. When omitted, every namespace is searched (first match).
</ParamField>

<ParamField body="duration" type="string" required>
  Snooze duration in Go duration format (e.g., `30m`, `1h`, `2h30m`). It must be positive; there is no maximum.
</ParamField>

The call adds `aiops.chatcli.io/snoozed-until` (now + `duration`, RFC 3339) and `aiops.chatcli.io/snoozed-by` (the **role** of the calling API key) to the Issue and returns the updated incident. Other body fields are ignored.

<Note>
The notification controller honors the snooze until `snoozed-until`:

- No state-change notification is sent, except `Resolved` (PagerDuty and OpsGenie need it to close the page).
- Escalation holds its current level. A level notification that falls inside the snooze is held (annotation `platform.chatcli.io/escalation-pending-notify`) and goes out when the snooze ends, and the level's timeout restarts from that moment.

Remediation is not affected. The `duration` must be positive: zero or a negative value returns `400`.
</Note>

<RequestExample>
```bash curl
curl -X POST -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"duration": "30m"}' \
  http://localhost:8090/api/v1/incidents/payment-service-oom-kill-1773933600/snooze
```
</RequestExample>
