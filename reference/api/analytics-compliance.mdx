title: "Analytics Compliance"
openapi: "GET /analytics/compliance"
description: "Returns a compliance report with incident, remediation, SLA, approval and audit metrics for a time window"
icon: "clipboard-check"
---

<ParamField query="namespace" type="string">
  Filter by Kubernetes namespace. Omit it to cover every namespace.
</ParamField>

<ParamField query="from" type="string">
  Start of the window, RFC 3339.
</ParamField>

<ParamField query="to" type="string">
  End of the window, RFC 3339. `from` and `to` are an absolute period: with both, the report covers exactly `[from, to]`; with only `from`, it runs to now; with only `to`, it is the 7 days ending at `to`; with neither, the last 7 days.
</ParamField>

## Report Contents

Minimum role: `viewer`. Resources created inside the window are aggregated:

- **IncidentMetrics**: total Issues, by severity and state, `MTTD` (`detectedAt − creationTimestamp`), `MTTR` (`resolvedAt − detectedAt`), mean remediation attempts
- **RemediationMetrics**: total plans, `SuccessRate` (percent, 0 to 100, over plans that ended `Completed` vs `Failed`/`RolledBack`), per action type, `AutoRemediatedCount` (plans `Completed`), `AgenticCount` (agentic plans)
- **SLAMetrics**: `ResponseSLAViolations` and `ResolutionSLAViolations`, `CompliancePercentage` (share of Issues with no violation; 100 when there are none), average response and resolution times. With IncidentSLAs in scope, a violation is what the IncidentSLA controller recorded on the Issue (`platform.chatcli.io/sla-violated`, `response` and/or `resolution`). Without any IncidentSLA, an Issue in state `Escalated` counts as a resolution violation and response violations stay `0`.
- **IncidentSLAs**: one entry per IncidentSLA in scope (`Name`, `Namespace`, `Severity`, `ResponseTime`, `ResolutionTime`, `CompliancePercentage`, `ActiveViolations`, `TotalViolations`, `TotalIssuesTracked`); omitted when there is none
- **ApprovalMetrics**: requests, auto/manual approved, rejected, expired, average decision time
- **AuditSummary**: total AuditEvents, by severity and by event type

<Note>
The report's keys are **PascalCase** (pinned by explicit JSON tags) and every duration (`MTTD`, `MTTR`, `Average*Time`) is an integer number of **nanoseconds**. `MTTR` here is measured from detection, while [`/analytics/mttr`](/reference/api/analytics-mttr) measures from Issue creation.
</Note>
