---
title: "Developer Feedback"
openapi: "POST /postmortems/{name}/feedback"
description: "Submits human feedback on a postmortem — allows the developer to rate remediation accuracy, record a corrected root cause, and add comments"
icon: "comment"
---

<ParamField path="name" type="string" required>
  PostMortem name (e.g., `pm-checkout-service-oom-kill-1773871200`)
</ParamField>

<ParamField query="namespace" type="string" default="default">
  Kubernetes namespace (only `default` is searched when omitted)
</ParamField>

<ParamField body="providedBy" type="string" required>
  Identifier of who is providing feedback (e.g., email or username). Maximum 253 characters.
</ParamField>

<ParamField body="remediationAccuracy" type="integer" required>
  Rating from 1 to 5 for the AI's automatic remediation accuracy
  - **1** — Completely wrong, did not resolve anything
  - **2** — Partially correct, but with significant issues
  - **3** — Reasonable, resolved but required manual adjustments
  - **4** — Good, resolved with minor observations
  - **5** — Excellent, perfect remediation
</ParamField>

<ParamField body="overrideRootCause" type="string">
  Human-provided root cause, stored in `feedback.overrideRootCause` next to the AI analysis (the AI `rootCause` field itself is not rewritten). Maximum 4096 characters.
</ParamField>

<ParamField body="comments" type="string">
  Additional comments about the postmortem or remediation. Maximum 4096 characters.
</ParamField>

## When to Use

After reviewing a postmortem in the Dashboard, the developer can provide structured feedback:

1. **Rate the remediation**: score from 1 to 5 the accuracy of the automated action
2. **Correct root cause**: record the right root cause if the AI was wrong or imprecise
3. **Add context**: comments with information the AI did not have access to

Feedback is displayed directly in the Dashboard and persisted in the PostMortem CR status.

<Note>
Requires `operator` role or higher. The `providedBy` field is mandatory for traceability.
`remediationAccuracy` must be 1 to 5 (`0` or a missing value returns `400`). Submitting feedback again overwrites the previous feedback. On concurrent modification, the API returns `409 Conflict`.
</Note>
