---
title: "Get Incident Timeline"
openapi: "GET /incidents/{name}/timeline"
description: "Returns the event timeline recorded in the incident's PostMortem"
icon: "timeline"
---

<ParamField path="name" type="string" required>
  Name of the Issue resource (e.g., `payment-service-oom-kill-1773933600`)
</ParamField>

<ParamField query="namespace" type="string">
  Only look for the PostMortem in this namespace. When omitted, every namespace is searched.
</ParamField>

The timeline is read from the **PostMortem** whose `issueRef` is this incident (`status.timeline`). A PostMortem is generated when a RemediationPlan of the incident finishes (resolved or contained), so an incident that is still being analyzed or remediated, was escalated without a finished plan, or was resolved manually has **no timeline yet** and returns `404`.

Event `type` values written by the operator are `detected`, `action_executed`, `action_failed` and `resolved`; in agentic mode each step becomes one event whose `detail` includes the AI reasoning. The list is not paginated (`page` is always 1).
