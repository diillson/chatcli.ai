Both endpoints live at the **root** of the REST API server — `http://<operator-host>:8090/healthz` and `/readyz`, **not** under `/api/v1` — and need no API key. They report on the REST API server itself.

<Note>
These are **not** the endpoints Kubernetes probes. The operator Deployment's liveness and readiness probes use the controller-runtime endpoints `/healthz` and `/readyz` on the health port **8081** (chart value `health.port`), which only check that the manager process is alive. Use the 8090 endpoints below for external monitoring of the API.
</Note>

## Liveness Check

```
GET /healthz
```

Always returns `200 OK` while the REST API server is serving. No authentication required.

<ResponseExample>
```json Response 200 — /healthz
{
  "status": "ok",
  "timestamp": "2026-03-19T15:00:00Z"
}
```
</ResponseExample>

## Readiness Check

```
GET /readyz
```

Lists Issues through the Kubernetes API (limit 1, 5-second timeout). Returns `200 OK` when that succeeds and `503 Service Unavailable` with the error text in `status` when it fails (API server unreachable, missing RBAC, CRD not installed).

<ResponseExample>
```json Response 200 — /readyz
{
  "status": "ready",
  "timestamp": "2026-03-19T15:00:00Z"
}
```
</ResponseExample>

<ResponseExample>
```json Response 503 — /readyz
{
  "status": "not ready: context deadline exceeded",
  "timestamp": "2026-03-19T15:00:00Z"
}
```
</ResponseExample>
