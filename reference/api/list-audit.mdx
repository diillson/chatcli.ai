---
title: "List Audit Events"
openapi: "GET /audit"
description: "Returns the AuditEvent records the operator's controllers write"
icon: "list"
---

<ParamField query="namespace" type="string">
  Filter by the namespace of the AuditEvent. Omit it to list every namespace.
</ParamField>

<ParamField query="type" type="string">
  Filter by `eventType` (exact match), e.g. `issue_created`, `issue_resolved`, `issue_escalated`, `issue_contained`, `remediation_started`, `remediation_completed`, `remediation_failed`, `approval_requested`, `approval_approved`, `approval_rejected`, `approval_expired`, `notification_sent`, `slo_violation`, `sla_breach`
</ParamField>

<ParamField query="severity" type="string">
  Filter by severity: `info`, `warning`, `critical`
</ParamField>

<ParamField query="resource" type="string">
  Filter by the affected resource **name** (exact match on `resourceName`)
</ParamField>

<ParamField query="from" type="string">
  Only events at or after this RFC 3339 timestamp (`spec.timestamp`, falling back to the creation time)
</ParamField>

<ParamField query="to" type="string">
  Only events at or before this RFC 3339 timestamp
</ParamField>

<ParamField query="page" type="integer" default="1">
  Page number
</ParamField>

<ParamField query="pageSize" type="integer" default="20">
  Items per page (maximum 100)
</ParamField>

Minimum role: `viewer`. AuditEvents are written by the operator's controllers (Issue, Remediation, Approval, Notification, SLO and SLA reconcilers), so the actor is always a controller. Calls to this REST API (acknowledge, approve, runbook edits and so on) are **not** recorded as AuditEvents; the operator only logs them as `[REST]` lines in its own log.

`detail` flattens `spec.details` into `key=value` pairs joined by `; ` (map order, so the pair order is not stable). Items are not sorted.
