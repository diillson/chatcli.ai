---
title: "Federation Correlations"
openapi: "GET /federation/correlations"
description: "Returns cross-cluster issue correlations read from Issue annotations"
icon: "diagram-project"
---

Minimum role: `viewer`. Takes no parameters. Lists the Issues of this cluster that carry a cross-cluster correlation ID, one item per distinct ID.

When the same `signalType` is active in 3 or more clusters, the federation controller's `CorrelateAcrossClusters` writes `platform.chatcli.io/cross-cluster-correlation` (`xcluster-<id>`) and `platform.chatcli.io/affected-clusters` (the number of clusters) on every matching Issue and raises `spec.severity` to `critical`, marking the ones it raised with `platform.chatcli.io/elevated-severity: "true"`. A group keeps one ID: a new matching Issue joins the ID an earlier Issue already carries.

## Correlation Fields

| Field | Source |
|-------|--------|
| `correlationId` | Annotation `platform.chatcli.io/cross-cluster-correlation` (the legacy `platform.chatcli.io/correlation-id` is still read) |
| `issue`, `namespace`, `severity`, `signalType` | The first Issue seen with that ID |
| `correlatedClusters` | Annotation `platform.chatcli.io/affected-clusters`, a count as a string (the legacy `platform.chatcli.io/correlated-clusters` is still read) |
| `elevated` | Annotation `platform.chatcli.io/elevated-severity` is `"true"` |
| `cascade` | Annotation `platform.chatcli.io/cascade-detected` is `"true"` |

A cascade that `DetectCascade` marked (`cascade-detected`, `cascade-source-cluster`, `cascade-source-issue`) appears here only when the Issue also carries a correlation ID.
