---
title: "Get PostMortem"
openapi: "GET /postmortems/{name}"
description: "Returns the postmortem of an incident: summary, root cause, timeline, executed actions and feedback"
icon: "magnifying-glass"
---

<ParamField path="name" type="string" required>
  PostMortem name (`pm-<issue name>`, e.g., `pm-checkout-service-oom-kill-1773871200`)
</ParamField>

<ParamField query="namespace" type="string" default="default">
  Kubernetes namespace. Unlike the incident endpoints, this one does **not** search all namespaces: without `namespace` it looks only in `default`.
</ParamField>

Minimum role: `viewer`. `spec` and `status` carry the **same** flattened object. Besides the fields shown, an item can carry `reviewedAt`, `requiresHumanAction` and `requiredAction` (set when the incident was contained and a human must restore the workload), and `chaosInduced`/`chaosExperiment` (when the Issue was correlated with a ChaosExperiment). Empty fields are omitted.

The REST projection does not include every PostMortem status field. Metric snapshots, blast radius, git correlation, SLI impact, trending, GitOps context, log analysis summary and cascade chain are only on the resource: `kubectl get postmortem <name> -n <namespace> -o yaml`.
