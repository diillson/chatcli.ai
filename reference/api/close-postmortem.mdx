---
title: "Close PostMortem"
openapi: "POST /postmortems/{name}/close"
description: "Closes a postmortem after review, marking it as finalized and accepted by the team"
icon: "lock"
---

<ParamField path="name" type="string" required>
  PostMortem name (e.g., `pm-checkout-service-oom-kill-1773871200`)
</ParamField>

<ParamField query="namespace" type="string" default="default">
  Kubernetes namespace (only `default` is searched when omitted)
</ParamField>

<ParamField body="reviewer" type="string">
  Identifier of the person closing the postmortem. Stored in the annotation `aiops.chatcli.io/reviewed-by`.
</ParamField>

<ParamField body="notes" type="string">
  Final notes. Stored in the annotation `aiops.chatcli.io/review-notes`, only when `reviewer` is also sent.
</ParamField>

## PostMortem Lifecycle

```
Generated (on incident resolution or containment)
      ↓
  State: Open
      ↓
  POST /review → State: InReview
      ↓
  POST /close → State: Closed
```

The call sets `status.state` to `Closed` and `status.reviewedAt` to the current time. Minimum role: `operator`. The REST handler has no state guard (closing twice succeeds, and `/review` can reopen a closed postmortem), so `Closed` is a status, not an immutability guarantee.

<Warning>
**Contained incidents need an acknowledgement first.** When the postmortem has `requiresHumanAction: true` (the operator contained the incident and a human must restore the workload), `/close` still returns `200`, but the PostMortem controller reverts the state to `Open` on its next reconcile unless the annotation `aiops.chatcli.io/human-action-acknowledged` is set. Call [Acknowledge Human Action](/reference/api/ack-human-action-postmortem) before closing.
</Warning>
